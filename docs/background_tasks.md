# 后台任务的工具块生命周期

## 交互

- Shell 与 Agent 的后台执行保留在原调用位置，按发起顺序阅读。
- 运行中字形保持动作形状，以现有运行色脉冲；结果列显示“后台运行中”。
- 完成、失败、停止和中断原位更新。Shell 展示退出码和实际输出，Agent 展示 Markdown 最终回复。
- 完成不产生 Notice、独立消息、自动展开或滚动。
- 工作段摘要独立统计后台运行数；主助手空闲后仍可观察后台任务。
- TaskOutput 归入原工具块；查询错误保留在块内。找不到原任务时保留独立工具行。
- SendMessage 开启新的会话交互，回复自动回投调用会话。TaskStop 保留独立停止动作，原任务同步变为已停止。
- 状态更新保留用户的展开选择。运行状态与主助手是否生成分开计算。

## 领域与传输

- `BackgroundTask` 是强类型任务快照，包含任务身份、状态、输出、退出码及截断信息。
- 启动和查询的 `ToolResult` 携带快照；后台完成 reminder 所在 `Turn` 携带最终快照。
- 原始调用与回执保留；JSONL 追加记录最终结果，不重写历史工具结果。
- 模型仍接收原有 reminder 并按现有规则自动续跑。供应商协议不变，UI 不解析 reminder 正文。
- `BackgroundTaskUpdated` 驱动 `SessionView.background_tasks`，Web 首帧及 SSE 增量传递相同投影，TUI 使用相同状态源。
- 重载时按历史快照重建投影；尚为运行中的任务标为已中断，保留已有输出。任务不跨进程恢复。
- Shell 任务 ID 全局唯一，防止重载、回退后复用 ID 污染旧工具块。

## 完成与持久化时序

1. 工具回执落盘，同时发布启动或查询快照。
2. 后台完成时立即发布结构化状态，排队投递 reminder。
3. 在工具结果已配对的安全轮隙追加 reminder 与最终快照，之后才调用模型。
4. 空闲完成路径先持久化结果再组装模型；取消或调用失败收尾时同样冲刷完成队列，保持原有“不自动续跑”行为。
5. 回退按保留历史重建任务投影；仍在运行的任务继续执行，完成时不向已删除的工具块添加状态。

## 验证重点

- 完成早于启动回执提交时，最终状态不会被运行态覆盖。
- 查询和完成不重复增加执行数，错误与停止状态可追溯。
- 后台 Agent 回复、失败及空回复均能显示并持久化。
- 刷新、SSE 重连、回退、进程重启及 ID 隔离。
- 浅色/深色与窄屏布局，保持工具块展开状态。

## 自动唤醒

- 启动后台 Shell、后台 Agent 或发送跨会话消息时，运行时自动登记异步工作。
- 模型没有可推进的工作时结束响应，会话保持空闲并监听事件；等待期间不调用模型、不计时轮询。
- 任一结果到达，空闲会话自动续跑；忙时入队，在工具调用与回执配对后注入。一次轮隙内已到达的结果共同交给模型。
- 完成通知经会话命令队列可靠投递；Shell 结果持久化后才确认消费。会话回复通过独立回执捕获，后续轮次不会覆盖结果。
- CLI 输出通道及程序化投递回执保留到后台工作和续跑完成。子代理本轮结束时若仍有后台工作，其最终报告在续跑结束后返回。
- 用户停止或模型调用失败后暂停自动续跑，后续结果仍更新工具块并持久化；新输入恢复正常调度。
- TaskOutput 用于按需查看进度或读取更多输出；模型无需调用工具等待完成。
- 后台工作沿用进程内生命周期，不跨进程恢复；常驻命令由 TaskStop 或退出进程终止。
